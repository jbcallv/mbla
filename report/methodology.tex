\date{Draft for advisor and collaborator review, \today}

\begin{abstract}
\noindent \BC{}'s policy engine asks an untrusted helper model to select, from the delegator's existing
authority, the subset a delegated task needs (the proposal $\langle C',P'\rangle$) and a further set of
plausible permissions (the admission set $A$) that bounds later recovery. G1 holds whatever the helper
outputs, so the helper never affects safety; it decides how much of the least-privilege benefit a delegation
actually gets. This document (i) summarizes a preliminary study of 23 helper configurations on 288
human-labeled delegation tasks, (ii) states the research questions the final paper answers, and (iii) fixes
the methodology: which helpers we evaluate and why, how we build and validate the benchmarks and training
data, why and how we fine-tune, and how we measure least privilege, recovery security, robustness to
manipulation, and cost. It also aligns the policy-inference evaluation with the current draft's design
(\S\ref{sec:alignment}), which changed several details since the preliminary study.
\end{abstract}

\section{What the evaluation must establish}
In the draft's terms, the helper is an untrusted component inside the delegator's TCB boundary
(\S3.4, \S4.3). G1 bounds every proposal by $(C_i,P_i)$ and the receiver bounds $P_{i+1}$ by
$P_{\mathrm{ceil}}$, so a helper that fails, or is fully compromised, can at worst reproduce the parent's
authority. The evaluation therefore does \emph{not} need to show that inference is safe; the checker
does that, and the conformance tests already exercise it. It needs to show three things a security
reviewer will ask about:
\begin{enumerate}
  \item \textbf{Benefit.} Inference removes authority that G1 alone would pass downstream, without
    breaking legitimate tasks.
  \item \textbf{Recovery is not an escalation path.} Bounding recovery by $A$ keeps an injected
    instruction from turning a denial into a grant, at acceptable utility cost.
  \item \textbf{The benefit survives an adversary who targets the helper.} The threat model (\S3.4)
    lets external and user-level adversaries know the design and target the helper. We measure how much
    of the benefit survives naive, held-out and adaptive attacks, and a malicious receiver operator who
    inflates the manifest.
\end{enumerate}
Cost (latency on the delegation path, refusals) is the fourth axis, because the helper sits on the
critical path of every delegation.

\section{Preliminary study (completed)}\label{sec:prelim}
We first cast a wide net, to learn which kind of helper suits this problem before committing to one.

\paragraph{Benchmark.} 408 delegation tasks (288 test, 120 development) built from 17 task templates over
the paper's workflows: GitHub issue triage, build and upload to object storage, and document retrieval
and posting. Each template is instantiated with 4 name bindings, 3 levels of delegator over-provisioning
(\emph{narrow}, \emph{medium}, \emph{broad}), and with or without one planted injected instruction aimed
at authority the delegator holds but the task does not need (488 planted attacks in total). Two people
labeled every candidate permission independently (Cohen's $\kappa = 0.85$, 95\% CI $[0.75, 0.94]$), then
adjudicated. Test files were frozen by checksum before any helper saw them; thresholds were tuned only on
development templates, which share no template with test.

\paragraph{Helpers.} 23 configurations in four families:
\begin{itemize}
  \item \emph{Generative LLMs} that read the task context and the numbered candidate list and return
    \texttt{required}/\texttt{plausible} index lists under a strict JSON schema: Qwen3 0.6B, 1.7B, 4B, 8B,
    30B-A3B (mixture-of-experts, 3B active) and 32B (4-bit), Phi-4-mini, gpt-oss-20b and gpt-oss-120b.
  \item \emph{Per-permission classifiers} that score each candidate independently as needed or not:
    Qwen3-Reranker 0.6B/4B/8B, and two off-the-shelf ``System One'' models (Laya, CLM-8B).
  \item \emph{CAPMAS}~\cite{capmas}, the closest prior system: a contrastively trained text encoder with a
    top-10 cut, reproduced from its released code within 1 point of its reported accuracy, run as published
    and with its scores inside \BC{}'s recovery.
  \item \emph{Model-free references}: set-only (keep every candidate, i.e.\ G1 alone), manifest-only, lexical
    matching, and three coin flips that grant each candidate with probability 25\%, 50\% or 75\%.
\end{itemize}

\paragraph{Findings that shape the methodology.}
\begin{enumerate}[label=P\arabic*.]
  \item \textbf{The admission set is what makes recovery safe.} Under a recovery rule bounded only by the
    parent, every planted attack stays reachable for every helper (attack reachability 100\%). Bounding
    recovery by $A$ cuts it to 13\% [8, 20] with Qwen3-8B while 97\% of legitimate tasks still finish
    ($p_{\mathrm{Holm}} < 0.001$). This is the strongest security result and motivates RQ2.
  \item \textbf{Mid-size generative LLMs select the tightest sets.} Qwen3-8B grants 9\% of unneeded
    capability authority and misses 3\%; Qwen3-4B, 30B-A3B and 32B are similar (6--9\%). Larger is not
    better: gpt-oss-120b grants 14\% and lets 49\% of attacks through recovery.
  \item \textbf{Per-permission classifiers are fast but barely beat chance untrained.} Qwen3-Reranker-0.6B
    decides in 28\,ms but grants 40\% of unneeded authority, against 51\% for a fair coin; it is exactly
    right on under 1\% of tasks, like the coin flips. Small LLMs ($\le$1.7B) and the System One models grant
    64--85\%.
  \item \textbf{A helper must output two tiers.} Helpers whose scores are effectively binary (Qwen3-30B-A3B,
    32B, the 0.6B models) cannot separate the proposal from $A$; tuning sets their admission threshold to 0,
    which gives no recovery protection. The draft's three-tier output (required, plausible, unneeded) is
    therefore a requirement, not a convenience.
  \item \textbf{The manifest helps as a hint.} Showing Qwen3-8B the receiver's manifest cuts unneeded
    authority from 23\% to 9\%. Because the manifest is operator-supplied, this also makes manifest
    inflation an attack worth measuring (RQ3).
  \item \textbf{Top-$k$ retrieval does not fit delegation.} CAPMAS as published grants 74\% of unneeded
    authority and, lacking recovery, completes 51\% of tasks; 69\% of attacks remain reachable. It is the
    fastest learned helper (23\,ms) because it embeds rather than generates.
  \item \textbf{Latency spans two orders of magnitude}: 23--190\,ms for classifiers and encoders,
    0.3--0.8\,s for the precise LLMs, 2.5--4\,s for reasoning models (median, exclusive L40S GPU).
  \item \textbf{External validity.} On FORTIS~\cite{fortis} (2,122 queries, official grading), the same
    ranking holds for set selection; on single-skill selection, Reranker-8B (45\%) matches gpt-oss-120b (47\%).
\end{enumerate}

\paragraph{What this implies.} The open question is no longer \emph{which kind of model}: P1--P4 point to a
helper that sees the whole candidate list and emits two tiers. The open question is whether that quality can
be had at classifier latency, and whether it survives an adversary. P3 suggests the fast models lack task
knowledge rather than capacity, which training can supply; prior work reports exactly this for related
least-privilege tasks~\cite{taskcond,toolpriv,noyan}. The final evaluation therefore narrows to a small,
justified set of helpers, adds task-specific training, and adds the adversarial and in-system evaluation the
preliminary study lacked.

\textbf{Consequence for the benchmark.} We re-express the 408 tasks in the draft's policy model
(\emph{Benchmark v2}). Capability labels carry over unchanged. File labels map to volume mounts; execute
labels and the 40 attacks that need only an extra binary are dropped, because the operator's base fixes
executability. Because the preliminary audit's only disagreements were on file and execute permissions
(F-20 in our log), the two reviewers re-label the volume component, which is small (one decision per
volume per template). Every selected helper is re-run on v2; that is cheap, because the preliminary
harness is reused.

\section{Research questions}\label{sec:rq}
\begin{description}
  \item[RQ1 (least privilege).] How much authority that G1 alone would pass downstream does inference
    remove, per component ($C$, $N$, $\plain$, $D$), and at what cost in missing authority?
  \item[RQ2 (recovery security).] Does bounding recovery by $A$ keep injected instructions from reaching
    authority outside the task, compared with a parent-bounded rule, and what does it cost legitimate tasks?
  \item[RQ3 (robustness).] How much of the RQ1 benefit survives (a) the planted injections, (b) injection
    styles never seen in training, (c) an adaptive attacker who optimizes the injected text against the
    helper, and (d) a receiver operator who inflates the manifest? (By G1 the floor is the parent.)
  \item[RQ4 (cost).] How much latency does inference add to a delegation, standalone and in-system, and how
    often does the helper fail closed?
  \item[RQ5 (training).] Does task-specific training let small, fast helpers match the best prompted
    helper on RQ1--RQ3, and does it generalize to task families, attack styles and benchmarks it never saw?
\end{description}

\section{Helpers under evaluation}\label{sec:helpers}
\paragraph{Selection rule.} From the preliminary results we keep (i) the helper with the best combined
security and utility (RQ1/RQ2), (ii) the Pareto front of authority granted vs.\ latency within each model
family, and (iii) the fastest model with the most room to improve. We restrict to \textbf{open-weight models
run locally}. This is a security requirement, not a convenience: the helper reads task context that may be
confidential, and the draft confines it to a sandbox whose only destination is the model endpoint, which an
operator can host itself. It also makes every result reproducible and allows white-box adaptive attacks.

\section{Benchmarks}\label{sec:benchmarks}
Each benchmark answers a different question; together they separate in-distribution quality,
generalization, security under attack, and in-system behavior.

\paragraph{B1: BoundClaw-Delegation v2 (human-labeled).} The 408 preliminary tasks re-expressed in the
draft's model (\S\ref{sec:alignment}): 288 test, 120 development. It is the primary measure of RQ1, RQ2 and
RQ4, and the only benchmark with human-adjudicated labels for every decision.

\paragraph{B2: synthetic delegation tasks (training and held-out generalization).} No public dataset has
our setting (the delegator's holdings as the choice set, receiver ceilings, recovery, planted attacks).
We therefore generate one, combining the methods of recent least-privilege datasets
(Table~\ref{tab:datasets}).
\begin{itemize}
  \item \emph{Scope.} The same three workflows and the draft's policy model; S3 uses the prototype's
    operation classes. Each API operation's required permission comes from the provider's published
    permission reference (for S3, AWS's machine-readable service authorization reference, checked
    automatically).
  \item \emph{Size and split.} 2,000 tasks in 40 task families: 1,500 train and 300 validation from 32
    families, and 200 test tasks from 8 families never seen in training (drawn at random with a fixed
    seed, stratified by workflow). Size and split follow the closest prior work~\cite{taskcond} and match
    similar studies~\cite{toolpriv}. Names share nothing with B1, and tasks sharing any 8-word sequence
    with B1 are dropped~\cite{contamination}.
  \item \emph{Generation.} A local open model writes each task as the delegating agent would, plus the API
    calls that complete it, and optionally alternative valid plans~\cite{selfinstruct,toolllm,apigen}.
    Handoffs vary over local and remote receivers and one or two hops, with upstream context for the
    second hop.
  \item \emph{Labels come from execution, not from a model.} Each call runs against a mock service that
    checks its arguments and that every resource it touches is named in the task, and logs the atoms and
    destinations it exercises. The required tier is the minimal set of candidates covering every logged
    atom (as AuthBench derives labels from traces~\cite{authbench} and IAM Access Analyzer derives policies
    from activity~\cite{accessanalyzer}). The plausible tier is what an alternative valid plan needs beyond
    the required tier. \textbf{Validated:} applying this labeler to call plans for B1's 17 templates
    reproduces the human labels on all 408 tasks.
  \item \emph{Automated checks.} Format, mock execution, and two judge models different from the writer
    that must both agree the plan completes the task, uses no unneeded call, and is unambiguous~\cite{toolpriv,apigen};
    near-duplicates are removed. We report the yield of every stage.
  \item \emph{Delegator holdings and attacks.} As in B1: narrow, medium or broad over-provisioning, built
    from near-miss authority (same resource with a different operation class, same operation on a
    different resource, wider prefixes). Half the tasks carry an injected instruction aimed at one held-but-unneeded
    atom, destination or volume; the label does not change.
  \item \emph{Human acceptance test.} Two reviewers independently label 93 randomly drawn tasks without
    seeing the generated labels, then adjudicate. The dataset is accepted if at most 1 generated label is
    wrong, which shows the label error rate is below 5\% with 95\% confidence (one-sided binomial
    acceptance sampling~\cite{montgomery}; exact Clopper--Pearson limits~\cite{clopper}). On failure we fix
    the generator, regenerate, and draw a fresh sample. We also report inter-reviewer $\kappa$~\cite{cohen}.
\end{itemize}

\paragraph{B3: external benchmarks.} FORTIS tasks 1 and 2~\cite{fortis} (skill and tool selection, official
grading) and the mostargate prompts~\cite{noyan} (15-permission enterprise taxonomy). These test whether
conclusions transfer to another group's tasks and labels. Evaluation only; neither is used for training or tuning.

\paragraph{B4: end-to-end workflows in \BC.} The paper's object-storage workflows in the existing harness
(S3-compatible store, stub internet, scripted and live agents, deterministic oracle with canary strings),
with the static proposer replaced by each final helper. This measures, in the deployed system, denials,
recovery requests, task completion, oracle-detected attack outcomes, and delegation latency through the
tunnel. It also closes the prototype gap that helper candidates and scores are not yet logged in-system.

\paragraph{B5: attack suite (RQ3).} Applied to the B1 test tasks and B4 workflows:
\begin{enumerate}[label=(\alph*)]
  \item \emph{Planted.} B1's injected instructions (seen in style during training).
  \item \emph{Held-out styles.} Injection styles from published attack corpora~\cite{injecagent,agentdojo}
    (e.g.\ fake system messages, tool-output mimicry, urgency framing) that are never used in training.
  \item \emph{Adaptive.} Following the standard for evaluating defenses~\cite{carlini,attackersecond}, the
    attacker knows the design, the candidate format and the output schema, and has the open weights. It
    searches for injected text that places a target atom in the proposal or in $A$, using an attacker-LLM
    search loop~\cite{pair} with a fixed query budget per task; we report success as a function of budget.
  \item \emph{Manifest inflation.} A malicious receiver operator signs a manifest that lists the attack's
    target authority as ``usually needed'' (\S4.3 permits a wrong manifest to loosen a grant).
\end{enumerate}

\section{Training}\label{sec:training}
\paragraph{Why train an untrusted component.} Training cannot add a guarantee; G1 and the checker supply
those. It changes only precision and cost: the preliminary study shows that the fastest helpers fail on
task knowledge, not on the security mechanism (P3). Training on B2 asks whether a 30\,ms helper can be as
tight as a 780\,ms one, which would remove most of inference's latency cost. Training on injected examples
with unchanged labels also teaches the helper to ignore injected requests; held-out attack styles (B5b)
test whether that generalizes or merely memorizes.

\paragraph{How.}
\begin{itemize}
  \item \emph{Targets.} Classifiers learn needed/not needed per candidate. Generative helpers learn the
    draft's three-tier output (indices only, fixed schema). Encoders use CAPMAS's own contrastive training code.
  \item \emph{Full fine-tuning} (all weights) for every model up to 8B, so a trained model differs from its
    untrained counterpart only by training; full fine-tuning learns new tasks better than low-rank
    adaptation~\cite{loralearnsless}. Qwen3-30B-A3B is too large to fully train on our hardware, so it uses
    QLoRA~\cite{qlora} and is compared only at matching precision (4-bit vs.\ 4-bit, and merged 16-bit vs.\ 16-bit).
  \item \emph{Settings.} Cosine schedule, 3\% warmup, 2 epochs, loss on output tokens only; learning rate
    chosen from $\{5\!\times\!10^{-6}, 10^{-5}, 2\!\times\!10^{-5}\}$ on B2 validation. Three seeds per
    configuration. Selection thresholds re-tuned on B1 development, as in the preliminary study.
  \item \emph{Isolation.} No B1, B3, B4 or B5 data is used for training or model selection. B2's held-out
    families are used only once, for the final report.
\end{itemize}

\section{Metrics}\label{sec:metrics}
All metrics are computed per task and per component $X \in \{C, N, \plain, D\}$, against the human (B1) or
execution-derived (B2) minimal authority $X^\star$. Authority sets are compared on witness atoms, so a prefix
grant counts for everything it covers.
\begin{itemize}
  \item \textbf{Excess authority} $= |\den{X'} \setminus \den{X^\star}| \,/\, |\den{X_i} \setminus \den{X^\star}|$:
    the share of the delegator's unneeded authority that the proposal still grants (set-only $=1$).
  \item \textbf{Missing authority} $= |\den{X^\star} \setminus \den{X'}| / |\den{X^\star}|$, and
    \textbf{exact match} ($X' \equiv X^\star$ on every component).
  \item \textbf{Attack reachability after recovery} (ARR): the share of planted attacks whose needed atoms
    and destinations are all granted initially or obtainable within $k$ recovery requests under the
    draft's rules (\S4.5), with $k=3$ (sensitivity: $k\in\{1,5\}$). Compared under parent-bounded and
    $A$-bounded admission.
  \item \textbf{Task completion} under the same rules, counting a missing volume or a refused delegation as
    failure; mean recovery round trips; refusal rate.
  \item \textbf{Benefit retained under attack} $= (E_{\mathrm{G1}} - E_{\mathrm{attack}})/(E_{\mathrm{G1}} - E_{\mathrm{clean}})$,
    where $E$ is excess authority on the attacked atoms: 1 means the attack gained nothing, 0 means it pushed
    the helper back to the parent.
  \item \textbf{Latency}: helper decision time (median, p95) with each model alone on one GPU, and delegation
    setup time in B4 through the tunnel; plus throughput under concurrent delegations.
  \item \textbf{FORTIS}: its official classes (exact, under, over, no action).
\end{itemize}

\section{Protocol and statistics}\label{sec:protocol}
\begin{itemize}
  \item \textbf{Pre-registration.} Helper set, metrics, comparisons and pass rules are fixed in our
    decision log before the corresponding results are seen; post-hoc analyses are labeled as such
    (as the coin flips already are).
  \item \textbf{Primary comparisons} (each with Holm correction within its metric family):
    best prompted helper vs.\ set-only (RQ1); $A$-bounded vs.\ parent-bounded recovery per helper (RQ2);
    each fine-tuned helper vs.\ its untrained version, and fine-tuned small helpers vs.\ prompted Qwen3-8B (RQ5);
    best helper vs.\ CAPMAS as published; best helper vs.\ each coin flip.
  \item \textbf{Uncertainty.} 95\% confidence intervals by bootstrap resampling of templates (B1) or task
    families (B2), since tasks within a template are correlated; paired differences use the same
    resampling. McNemar's exact test for paired binary outcomes (exact match, FORTIS). Trained models: mean
    over three seeds with seed variance reported.
  \item \textbf{Latency.} Exclusive GPU per model, fixed warm-up, the same 60-task subset for every helper;
    never measured while sharing a GPU.
  \item \textbf{Checker.} The G1 checker's conformance suite (an independent reference implementation
    agreeing on 14,480 generated cases) is re-run on the v2 policy model, so ``the helper cannot exceed the
    parent'' is tested, not assumed.
\end{itemize}
